# Wiki у ChatGPT

**Рекомендований спосіб — особистий скіл Wiki.** Він використовує ваше
підключення GitHub і не потребує Custom instructions чи окремого MCP-сервера.

## Встановлення

1. Підключіть GitHub у ChatGPT і надайте доступ до потрібних репозиторіїв.
2. Попросіть ChatGPT: «Встанови особистий скіл Wiki з
   kozaksv/claude-wiki-skill, директорія skills/wiki-github».
   У середовищі з підтримкою створення особистих скілів асистент встановить
   увесь пакет, включно з references/ і scripts/, та надасть посилання на нього.
3. Відкрийте новий чат і назвіть репозиторій та завдання. Налаштовувати
   кожний репозиторій у Custom instructions не потрібно.

Сам файл у GitHub ще не означає встановлення. Якщо створення особистих скілів
недоступне у вашому ChatGPT, скористайтеся доступним у вашому просторі
імпортом/каталогом скілів чи плагінів. Не всі поверхні ChatGPT мають однакові
можливості встановлення або GitHub-запису; встановлення скіла не додає прав.

## Як користуватися

- «Прочитай вікі example/project і поясни архітектуру».
- «Додай це рішення до вікі example/project».
- «Виправ інструкцію деплою і закоміть у master без PR».
- «Для цього проєкту за замовчуванням коміть вікі прямо в main».
- «Підготуй PR зі змінами до вікі».
- «Винеси історію інцидентів з цієї сторінки, залиш поточні правила».
- «Захисти concepts/recovery.md від автоматичного прибирання».

Запитання запускає читання. Прохання змінити знання запускає редагування.
Скіл читає потрібні джерела, готує пов'язані правки до сторінок, посилань,
індексу й журналу, перевіряє їх та зберігає обраним способом.

## Прямий коміт або PR

| Режим | Результат |
|---|---|
| «Закоміть у master/main», «без PR», встановлена користувачем перевага direct | Перевірений коміт у вибраній гілці та посилання на нього |
| «Зроби PR» або немає встановленої переваги | Окрема гілка та PR з описом і перевірками |
| У GitHub-підключення немає запису або правила гілки забороняють direct | Підготовлена правка і конкретне пояснення, що завадило її зберегти |

Перед прямим записом перевіряється актуальна вершина гілки. Конкурентні зміни
потрібно узгодити; force push не застосовується. Режим direct не вимагає PR
або повторного дозволу на вже запитаний коміт. Невдалий direct не підміняється
небажаним PR.

За бажанням підтримувач може записати вибір у frontmatter schema.md:
`write_mode: direct` / `write_mode: pull_request`, `write_branch: master`.
Це необов'язкова домовленість для вже дозволених змін; звичайне запитання
ніколи не дає дозволу на запис.

## Скіл і пакування плагіна

Скіл — достатній пакет поведінки для читання й змін через GitHub.
Плагін корисний для поширення через керований каталог команди. Маніфест
`.codex-plugin/plugin.json` експортує той самий `skills/wiki-github/`;
встановлювати обидва варіанти одночасно не потрібно.

Підтримувачі змінюють спільні контракти в references/ кореня репозиторію
і запускають `python3 scripts/build_skill.py`. CI перевіряє, що самостійний
пакет має актуальні копії. Каталог плагінів, публікація та інсталяція в
обліковий запис — окремі дії; наявність маніфесту їх не виконує.

Офіційні довідки:
[ChatGPT plugins](https://learn.chatgpt.com/docs/plugins),
[Build plugins](https://learn.chatgpt.com/docs/build-plugins).

## Сумісність

Старі вікі читаються без міграції. Каталог точних шляхів і версійований
захист можна додати під час обслуговування; див.
[команди підтримки](../references/wiki-maintenance.md).
Приватна gitignored телеметрія іншого клону недоступна через GitHub.
Тому перед руйнівними діями зі старою вікі потрібно з'ясувати її захист;
звичайне редагування або читання відсутність лічильників не блокує.
